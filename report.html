8. Recuperación del shell

La reconexión fue reforzada con recurso local empaquetado en desktop/electron/resources/connectivity/. Electron muestra primero esa pantalla local antes de intentar la URL remota; así una caída de DNS/TLS o una navegación colgada no deja la ventana blanca. Mientras la web está cargada, el proceso principal comprueba la URL remota cada 3 segundos y cambia a la pantalla local ante una pérdida de red; después reintenta volver a la última URL válida. Los estados de fallo y reconexión muestran un indicador Wi‑Fi con alerta para distinguir pérdida de conexión de carga normal; al recuperar se muestra check verde. did-fail-load solo actúa sobre el main frame y códigos de red recuperables; la disponibilidad se comprueba desde el proceso principal con net.fetch y timeout de 5 segundos. El backoff único es 2/4/8/15/30 segundos, el botón manual usa IPC, y la última URL remota válida queda solo en memoria. No se guardan tokens ni operaciones de negocio offline.

9. Recuperación de venta ambigua

Implementado en web/store/posCart.ts, web/modules/pos/components/PosScreen.tsx, api/src/modules/inventory y docs/pos-recovery-and-session-limits.md: antes de enviar se persiste intento SUBMITTING; al reiniciar se normaliza a UNKNOWN; la venta acepta Idempotency-Key tenant-scoped, replay seguro y consulta backend por clave; no hay retry automático de negocio.
